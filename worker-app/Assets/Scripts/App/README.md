# CoGaze.Worker.App

Bootstrap only. `WorkerBootstrapBehaviour` has two modes:

- **Editor rehearsal** (`editorRehearsal` on, editor only): the cue display with synthetic cues, a
  manual desk plane, main-camera poses, cycling the visualisations every 6 s. Open `Worker.unity`
  and press Play. Logs go to `Application.persistentDataPath/sessions`.
- **Live** (on device always; in the editor with `editorRehearsal` off): `WorkerLive` wires the
  WebRTC link (`signalingUrl`, e.g. `ws://<server-ip>:8765/signal`), passthrough capture with frame
  ids, the cue pipeline on the work surface, the condition/trial/clock responder, WorkerStatus at
  1 Hz and `pose.csv` at 30 Hz. Logs go to `persistentDataPath/sessions/<expert's session name>/`
  once the expert opens a session. Needs `com.unity.webrtc` (otherwise it logs an error and idles).

## Scenes

`Worker.unity` is the base scene and stays loaded: the Quest passthrough rig and the bootstrap.
Each visualisation's renderer lives in its own additive scene, `Cue_Ray` / `Cue_Circle` /
`Cue_Frustum`. `CueSceneLoader` loads the one the current condition names (`CueScenes.For`, derived
from the condition's `visualization`; `conditions.json` names no scenes) and hands its renderers to
the pipeline. It swaps only between trials; a change mid-trial is deferred and logged. Every load,
unload and failure is an `events.csv` row (`cue_scene_*`). Conditions differ only by which scene is
loaded, so a renderer change applies to every condition that uses it.

The scenes are generated by `Editor/WorkerSceneSetup.cs` (missing ones on project open, all of them
from **CoGaze → Recreate Worker Scenes**). `Worker.unity` is copied from `Tutorial.unity`, which
keeps the keyframe-capture rig for the environment line. A new visualisation needs a renderer and a
line in `WorkerSceneSetup.RendererType`. `GeometryProbe` runs only with the `COGAZE_PROBE` define.

The work surface is still `ManualWorkSurfaceBehaviour`; the QR surface (#23) replaces it here.
